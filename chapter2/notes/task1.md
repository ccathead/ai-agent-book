# Chapter 2 学习笔记

## 主线
**上下文决定 Agent 能力上限**——模型智力只决定下限，上下文质量决定上限。所有内容围绕"如何把任务相关信息高效、稳定地送到模型面前"展开。

## 五大机制

### 1. 消息结构（骨架）
API 消息列表 = 四种 role + tools 字段：
- `system` · 开发者写的规则（最高优先级）
- `user` · 用户输入
- `assistant` · 模型回复（含 tool_calls）
- `tool` · 工具结果（通过 `tool_call_id` 关联）

tools 不属于消息 role，而是请求顶层独立字段。每次调用都是**无状态**的——历史必须在请求里由 Agent 框架重建。

### 2. KV Cache（性能边界）
KV Cache 缓存的是「前缀 N 条消息里每个 token 的 K、V 向量」。在 causal attention 下，每个 token 的 K、V 由**它之前所有 token** 共同决定。

**为什么「改一条消息 → 改点之后全失效」**：
```
改第 k 条 → 第 k 条本身的 K、V 变了
  ↓
第 k+1 条算自己的 K、V 时依赖第 k 条
  ↓
第 k+1 条的 K、V 也变了
  ↓
K、V 错位像传染病一样向后扩散
  ↓
必须从第 k 条开始整段重算
```

**诉求是「稳定前缀」**，不是"有历史"：
- 改 system prompt / tools 字段 → 全失效（破坏前缀起点）
- 在历史中间改一条 → 改点之后全失效
- 改点之后**追加**新消息 → 不影响缓存（旧前缀仍命中）

### 3. 压缩（信息密度）
实验 2-10 的 6 种策略是对**照基线**，不是 6 个备选答案：
- **1 无压缩**（基线）→ 超长溢出
- **2 逐页摘要** → 每个工具结果独立摘要，保留页内细节但丢跨页关系，多次 LLM 调用
- **3 合并摘要** → 全部拼接后一次总摘要，可能丢页级归属
- **4 上下文感知摘要** → 结合当前查询做聚焦摘要
- **5 带引用的上下文感知** → #4 + 保留来源 URL，可回溯原文
- **6 自适应窗口化** → 阈值触发 + 批量压缩 + `[COMPRESSED]` 标记防重复压缩

**生产级是分层组合**（§2.3.4），不是单选：
```
工具结果预算（落盘 + 摘要预览）
  → 噪声直接删除（不做摘要）
  → API 层微压缩（服务端删，前缀不变）
  → 归档式摘要（每轮独立，git log 式）
  → 全量压缩 + 熔断器（最后兜底）
```

### 4. Skills（按需加载）
- **不是**"把领域知识写进 system prompt"
- 核心机制是**元数据先行**：SKILL.md 的 frontmatter 让模型先看到摘要（name + description），按需才加载正文
- 渐进式披露：模型"判断需要"时才读完整内容
- **代价**：把判断责任推给模型自己——元认知风险

### 5. 状态栏（确定性元信息）
- 把"工具调用次数 / 时间戳 / TODO / 错误计数"等结构化元信息由**代码**注入 system prompt
- **不依赖** LLM 从 history 里心算
- 状态的两种实现：
  - 改写 system prompt → 简单但**破坏 KV Cache 整个前缀**
  - 作为独立 message 注入 → 保留缓存但消息列表略增

## 反直觉的两个点
1. **KV Cache 真正诉求是「稳定前缀」**，不是「有历史」。空调用反而 KV Cache 命中率最高。
2. **Skills 的代价是把判断推给模型自己**——能加载错或漏加载，是元认知风险。

## 上下文腐化机制
- 不是"窗口不够长"——窗口还有富余时就发生
- 机制 1：注意力分散 → 单个 token 权重下降 → 「**检索**」变模糊
- 机制 2：跨多格做统计/汇总 → 「**思考**」类任务直接做不到
- 滑动窗口导致重复调用 = 腐化的极端形态

## 与上下文腐化互补的机制
- **状态栏**：把"心算"换成"检索"（直接读已算好的）
- **压缩**：减少"心算需要扫描的范围"
- **子 Agent 隔离**：让噪声根本不进入主上下文
