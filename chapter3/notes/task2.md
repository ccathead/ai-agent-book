# 用户记忆和知识库

## 主线

持久化记忆体系分两个尺度：
- **用户记忆**（个体）—— Agent 与单用户的跨会话个性化记忆
- **知识库**（群体）—— 面向所有用户共享的领域知识

两者底层技术共通（向量检索、知识压缩），面临同样的麻烦（冲突、过期、检索不准）。

---

## 用户记忆（个体尺度）

### 定义

用户记忆是**持久的服务**——不存每句对话，而是用额外的 LLM 调用**提取、压缩、审查**对未来有用的事实。

提取结果应同时满足三条规则：
- **选择性**：丢弃"搜索返回 3 个选项"这类短期细节
- **抽象化**：把"靠窗座位"归纳为长期偏好
- **结构化**：用可检索的字段保存事实

### 评估标准：三层次框架

设计记忆系统前先确立评估标准。综合 LoCoMo 等基准与商业记忆产品实践，记忆能力可归纳为三层次：

1. **基础回忆**——准确存储和检索用户直接提供的、结构化的、无歧义的信息
2. **多会话检索**——面对来自不同对象、不同时期的多段会话，检索出所有相关信息并推理判断
3. **主动服务**——综合多个会话的信息，提供具有预见性的主动帮助

### 记忆设计的三维度

| 维度 | 回答的问题 | 具体分类 |
|------|-----------|---------|
| **放哪里** | 信息存在哪一层？ | 轨迹（当前会话）/ 长期记忆（跨会话）/ 业务状态（任务阶段）|
| **怎么放** | 怎么存？ | Simple Notes / Enhanced Notes / JSON Cards / Advanced JSON Cards |
| **存什么** | 信息内容是哪种？ | 情景记忆（具体事件）/ 语义记忆（一般知识）/ 程序记忆（行为流程）|

三套体系是正交维度——可自由组合。

#### 维度一：放哪里（记忆层次）

- **轨迹（Trajectory）**：一次 Agent 运行过程的完整历史记录，按时间追加、只增不改（append-only）
- **用户长期记忆**：跨会话、跨实例的持久化存储，通常以键值对形式与用户 ID 绑定
- **业务状态**：开发者定义的高层状态抽象（"需要澄清"、"处理请求中"、"等待付款"等任务阶段）

#### 维度二：怎么放（四种存储格式）

四种格式代表粒度和结构复杂度的递进：

- **Simple Notes**：每条记忆是最小的、不可再分的事实（"用户邮箱：john@example.com"）。开销极低、支持 O(1)，但信息关联性完全丢失
- **Enhanced Notes**：整体视角，每条记忆保存为包含完整上下文的段落。保留叙事结构，但存储冗余、更新复杂
- **JSON Cards**：三层嵌套结构（类别→子类别→键值对，如 `personal.contact.email`），模拟人类分类方式。支持部分更新
- **Advanced JSON Cards**：每张卡片加入**信息来源叙事（backstory）**、**主体身份（person）**、**与用户关系（relationship）**、**时间戳**。解决消歧问题

实践选择标准：**关键且少量**用 Advanced JSON Cards 保证可检索性；**大量且非关键**用 Simple Notes 降本。

#### 维度三：存什么（认知科学类型）

来自认知科学的三类记忆：
- **情景记忆**：具体事件（"上周三和同事吃了晚餐"）
- **语义记忆**：一般性知识（"意大利首都是罗马"）
- **程序记忆**：行为模式与流程（"如何骑自行车"）

## 知识库（群体尺度）

### RAG 基础

典型 RAG = **检索器**（从知识库找出相关片段）+ **生成器**（LLM 拿到片段作为上下文生成答案）。

**核心流程**：检索相关片段 → 注入上下文 → LLM 基于上下文生成答案

#### 检索前的离线预处理：分块（Chunking）

- **固定大小切分**：按固定 token 数（如 512）切分，相邻块保留重叠
- **递归/结构感知切分**：按文档自然边界（章节、段落、句子）递归切分
- **语义切分**：计算相邻句子嵌入相似度，在"语义断崖"处下刀

#### 嵌入：稠密 vs 稀疏

- **稠密嵌入**：深度学习把文本映射到向量空间——语义相近内容向量距离近（如 BGE-M3）
- **稀疏嵌入**：传统词袋模型 + BM25——精确匹配关键词

### 知识的组织与检索

**原始案例或文档不加处理直接放进知识库是远远不够的**。需要组织方式：

#### 1. 结构化索引

- **RAPTOR**（树状层次）：递归抽象树
- **GraphRAG**（实体关系图）：基于知识图谱的检索增强生成

应用场景：跨文档综合、多层次导航

#### 2. 文件系统范式

不将上下文视为扁平的向量碎片或图谱节点，而是映射为**虚拟文件系统中的目录和文件**，每个条目拥有唯一 URI：

```
viking://
├── resources/          # 外部知识：文档、代码库、网页
├── user/memories/      # 用户记忆：偏好、习惯
└── agent/              # Agent 自身：技能、经验
    ├── skills/
    └── memories/
```

#### 3. 智能体化 RAG

把 RAG 从**固定数据处理流程**升级为**由 Agent 主导的动态迭代探索**：

- 传统 RAG：被动"检索-生成"管道，能力上限低
- 智能体化 RAG：Agent 用 ReAct 模式（思考→行动→观察）迭代搜索，复杂问题多轮检索逼近答案
