# 实验1-1 上下文的关键作用

## 环境配置

- **任务**：
  Multinational Budget（多国预算）（默认任务）
- **模型**：`Qwen/Qwen3.5-122B-A10B` via 硅基流动
- **工具集**：`parse_pdf`、`convert_currency`、`code_interpreter`
- **运行命令**：
  ```bash
      main.py --mode ablation --provider siliconflow --model "Qwen/Qwen3.5-122B-A10B"
  ```

## 上下文组成

上下文有 系统指令、工具定义、思考过程、历史记录、工具结果五个组件。

承接 [task0.md](task0.md) 的核心公式：

```
Agent = LLM + 上下文 + 工具
其中 上下文 = prompt + tools schema + 历史消息 + 模型回答（推理） + 工具执行结果
```

## 实验设计

每次只关掉一个组件，其他保持不变，观察模型表现差异——这就是 **ablation（消融）**：5 个 mode，每个 mode 对应关掉一个组件。

| Mode | 关掉的组件 |
|---|---|
| `full` | 无（baseline） |
| `no_history` | 历史消息/历史工具调用 |
| `no_reasoning` | 模型的思考过程 |
| `no_tool_calls` | 工具定义 schema |
| `no_tool_results` | 工具执行结果回填 |

## 实验结果

| Context Mode | 完成 | 工具调用 | 推理步 | 耗时 | Figures | 终端答案 |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| `full` | ✓ | 6 | 2 | 39.4s | saw tools | 有效 |
| `no_history` | ✗ | 10 | 10 | 57.7s | - | **未完成** |
| `no_reasoning` | ✓ | 6 | 1 | 50.9s | saw tools | 有效 |
| `no_tool_calls` | ⚠ | 0 | 1 | 21.9s | **UNSUPPORTED** | 数字无观测 |
| `no_tool_results` | ⚠ | 8 | 5 | 48.1s | **UNSUPPORTED** | 数字无观测 |

**Terminal Response Rate: 4/5** —— 表面看 4/5 完成，但其中 2 个其实是**幻觉式完成**（harness 抓到 7 个无观测来源的数字）。真正有效的只有 2/5（full + no_reasoning）。

## 详细解读

### `full` —— 唯一真正完成的 baseline

4 轮迭代、6 次工具调用、2 步推理、39 秒给出基于真实数据的答案。完整跑通 `parse_pdf → convert_currency → code_interpreter` 链路。

### `no_history` —— 唯一**真正失败**

耗尽 10 轮仍未终止，反复重试同一个 PDF 下载（每次失败都不知道自己刚才试过了）。**没有历史记忆 = 失去进度跟踪能力 = 死循环**。

### `no_reasoning` —— 能完成，但效率下降

| 指标 | full | no_reasoning | 差异 |
|---|:-:|:-:|:-:|
| 工具调用 | 6 | 6 | = |
| 推理步 | **2** | **1** | -50% |
| 耗时 | 39s | 51s | **+30%** |

模型照常调工具，但**少了显式的"先思考再行动"**——结果一样，过程更混乱。说明 **reasoning 是锦上添花，不是必要组件**：缺它仍能完成，但计划性变差。

### `no_tool_calls` —— 纯幻觉

1 轮直接给答案，0 次工具调用，但**编出 7 个数字**：

```
[11968000.0, 2393600.0, 2300000.0, 1656000.0,
 349600000.0, 1932000.0, 2944000.0]
```

harness 检测到这些数字无任何工具观测来源，标为 `UNSUPPORTED`。**没有工具定义，模型就是个聊天机器人**——只能靠"看起来合理的数字"填空。

### `no_tool_results` —— 做了等于没做

调了 8 次工具（甚至比 baseline 还多），思考了 5 步，但**所有数字仍无观测来源**——模型根本看不到工具返回。说明 **"调工具"只是手段，"看到结果"才是目的**。模型对着自己生成的内容继续推理，迭代越多，幻觉越深。

## 关键结论

| 组件 | 缺它的后果 | 严重度 |
|---|---|:-:|
| **历史** | 死循环，无法完成任务 | ⚠⚠⚠ |
| **工具调用** | 纯文字回答，所有数字都是幻觉 | ⚠⚠⚠ |
| **工具结果** | 调了工具也白调，越做越错 | ⚠⚠⚠ |
| **推理** | 能完成，但效率下降 ~30% | ⚠ |

**重要性排序**：历史 ≈ 工具调用 ≈ 工具结果 > 推理

## 一句话总结

**上下文的每个组件都有不可替代的作用——历史让 Agent 不重复犯错，工具让 Agent 看到真实世界，工具结果让 Agent 相信自己的眼睛，推理让 Agent 不乱来。**
